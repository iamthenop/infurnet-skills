# Set builder plan

## Purpose

Prepare and issue a `builder-plan` describing an acceptable
implementation of the commissioned work.

## Required references

Read the following documents in full:

- [`master-workflow.md`](../master-workflow.md) — applicable
  handoff and alternate paths.
- [`builder-plan-template.md`](../../assets/builder-plan-template.md)
  — authoritative message structure.

Read the applicable workorder and its referenced contracts
and source artifacts.

## Procedure

### 1. Establish the implementation

Use the feasibility assessment to select an implementation
that satisfies the workorder within existing authority.

Identify the required changes, affected boundaries, and
execution sequence.

Choose internal implementation details consistent with
established contracts.

### 2. Establish the execution approach

Describe each planned change and its intended result.

Identify affected files and interfaces.

Account for approved dependencies, integration requirements,
and relevant repository state.

Explain material implementation trade-offs and their
consequences.

### 3. Establish validation

Map the workorder's completion criteria to concrete
validation activities.

Identify the evidence needed to demonstrate each required
outcome.

Include applicable checks required by governing standards.

### 4. Check readiness

Verify that the plan:

1. Satisfies the commissioned objective.
2. Covers the workorder's required obligations.
3. Remains within the authorized surface and mutations.
4. Preserves established contracts and design decisions.
5. Accounts for material implementation trade-offs.
6. Defines validation for the completion criteria.
7. Has sufficient authority to execute as proposed.

Resolve drafting defects before issuing the plan.

An unresolved decision requiring additional authority
follows the deviation-request path in the master workflow.

### 5. Issue the plan

Complete
[`builder-plan-template.md`](../../assets/builder-plan-template.md)
and issue the resulting `builder-plan` according to the
applicable handoff in the master workflow.

## Output

One completed `builder-plan` using the authoritative template.
